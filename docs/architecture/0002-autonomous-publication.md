# ADR 0002: 일일 게임의 자율 아케이드 공개

- 상태: 채택
- 날짜: 2026-07-16
- 대체 범위: ADR 0001의 수동 카탈로그 PR 절차

## 결정

라이카의 일일 제작은 로컬 후보 등록에서 멈추지 않는다. 검증된 게임 artifact를 기존 Vercel Blob에 올리고, 아케이드 preview와 production을 실제로 플레이해 확인한 뒤 완료한다.

공개는 관제 저장소의 결정론적 명령 하나가 담당한다.

```bash
node scripts/publish-game.mjs --publish --game games/YYYY/YYYY-MM-DD-slug
```

명령은 release 브랜치로 preview를 만든 뒤 검증한 같은 커밋만 `main`에 fast-forward한다. production 검증이 실패하면 해당 커밋을 되돌린다.

## 이유

매일 수동으로 Blob 경로, 카탈로그 해시, Vercel 배포를 맞추면 누락과 오타가 쌓인다. 반대로 게임 저장소마다 사이트를 만들면 저장소 분리의 장점은 남지만 운영 프로젝트가 365개로 늘어난다.

하나의 공개 명령이 불변 artifact, 카탈로그 포인터, preview와 production 스모크를 묶으면 저장소는 분리한 채 공개 품질을 반복할 수 있다.

## 권한 경계

기존 `laika` Vercel 프로젝트와 연결된 Public Blob store에 새 게임을 공개하는 일은 라이카의 기본 제작 권한에 포함한다.

다음 작업은 포함하지 않는다.

- 새 Vercel 프로젝트나 유료 리소스 개설
- 계정, 팀, 결제 수단, 도메인 변경
- Toss `.ait` 제출과 출시
- 광고, 결제, 개인정보 수집 추가
- 공개작의 파괴적 교체나 Blob 삭제

## 결과

- 일일 완료 조건에 운영 도메인 한 판 완주가 추가된다.
- 게임 `.studio.json`은 소스 커밋의 `local-preview` 상태를 유지한다.
- 실제 공개 상태는 아케이드 카탈로그가 소유하고, 관제 카탈로그가 이를 미러링한다.
- 인증이 막히면 라이카는 로컬 작업을 모두 끝낸 뒤 정확한 복구 명령을 안내하고, 인증 직후 공개를 재개한다.
