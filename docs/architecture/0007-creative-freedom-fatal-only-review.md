# ADR 0007: 창작 자유와 치명 결함 전용 출고 검사

- 상태: 채택
- 날짜: 2026-07-26
- 적용: sequence 22부터
- 대체 범위: ADR 0003의 아이디어·시각 기준, ADR 0005의 깊이 전제, ADR 0006의 목표 화면·약속 대조·플레이 가능성 차단 규칙

## 결정

게임 제작의 창작 제약은 하나다.

> 세로형 모바일 디바이스에서 터치로 플레이되는 웹 게임을 만든다.

장르, 규칙, 길이, 종료 유무, 난이도, 언어, 입력, 기술, 자원 규모, 기존 게임의
모방·변형·재창작 여부는 제작자가 정한다. DOM, Canvas, WebGL, WebGPU, 셰이더,
물리, 영상, 생성 이미지와 외부 자산을 동등하게 사용할 수 있다. 최근 작품과
비슷해도 공개를 막지 않는다.

테스트 가능성은 게임 디자인 조건이 아니다. 규칙의 결정론, 자동 완주,
플레이 가능성 시뮬레이션, 목표 화면, 전략 가독성, 깊이, 첫 행동 설명,
게임 오버와 재시작은 게임이 스스로 선택한 구조일 때만 기록한다.

체르파는 설계 심사자가 아니라 출고 검사자다. 다음 치명 결함만 공개를 막는다.

1. 빌드가 뜨지 않거나 필수 자산이 빠져 빈 화면·충돌이 난다.
2. 세로 모바일 화면에서 핵심 플레이 영역이 잘리거나 사용할 수 없다.
3. 화면에 보이는 주 입력을 실제 터치로 한 번도 수행할 수 없다.
4. 시작 직후 반복 충돌, 입력 잠김, 복귀 불능처럼 제품을 사용할 수 없다.
5. 검토한 소스와 공개할 빌드가 다르다.
6. 결제·개인정보 수집·새 유료 리소스처럼 운영자 승인이 필요한 동작이 승인 없이 들어갔다.

난해함, 미완주, 불친절한 안내, 낮은 깊이, 취향, 목표 화면과의 차이,
기존 게임과의 유사성, 자동 테스트 불가, 종료·점수·재시작 부재는 차단 사유가
아니다. 관찰에는 남기되 그대로 공개한다.

## 검증 계약

sequence 22부터 제작 잠금과 공개 게이트는 다음 증거만 요구한다.

- 현재 소스 해시에 결속된 부팅 스모크
- 콘솔·페이지 오류 0
- 포털 CSP와 필수 자산 로드
- 세로 모바일 뷰포트에서 핵심 영역이 보임
- 실제 포인터 입력 1회 이상과 그 뒤의 화면 반응
- `design-review.json`의 fatal-only 검사와 현재 sourceHash

게임이 종료·결과·재시작을 제공하면 해당 경로를 검사한다. 제공하지 않으면 만들게
하지 않는다. 프로덕션 스모크도 같은 원칙으로 짧은 상호작용 뒤 오류와 자산 상태를
확인하며 완주를 의무화하지 않는다.

## 공개 기록

목표 화면과 `designProcess.scenes`는 선택 사항이다. 체르파 공개 기록에는 치명
검사 결과와 비차단 관찰을 적을 수 있다. 공개 후 무르는 완주 여부와 상관없이
실제로 경험한 범위만 기록한다.

제작 단계는 권리 판단을 입력으로 받지 않는다. 외부 자산과 참고 작품은
`ART.md`에 사실대로 기록하되 출고 검사에서 창작물을 교정하지 않는다. 법적 판단,
Toss 출시, 비용·계정·도메인 변경은 게임 디자인과 분리된 운영자 결정으로 남는다.

## 이유

이전 공정은 품질을 높이려다 테스트하기 쉬운 결정론적 판정, 하나의 상호작용,
목표 화면, 깊이 축과 감산을 동시에 요구했다. 제작자는 자유로운 현상보다 게이트가
측정할 수 있는 규칙을 선택했고, 설명 수단까지 줄이면서 해독해야 하는 게임이
나왔다.

제약을 제거해 확보한 자원은 규칙을 검증 양식에 맞추는 데 쓰지 않고 제작자가
원하는 기술, 장면, 사운드와 규모에 다시 투자한다. 다양성은 한 게임을 이전 게임과
다르게 만들라는 금지 목록이 아니라 여러 편이 쌓인 결과로만 관찰한다.
