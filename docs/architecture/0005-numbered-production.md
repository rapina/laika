# 0005 · 연번 제작

## 결정

게임 제작 단위를 하루(날짜)에서 연번(sequence)으로 바꾼다. 게임의 정체성은 카탈로그 `sequence`이며, 같은 날짜에 여러 게임을 만들고 공개할 수 있다. 날짜는 실제 제작일을 기록하는 메타데이터로만 남는다.

진행 중(미완성 또는 미공개) 게임은 한 번에 하나만 둔다. 완성·공개가 끝나면 곧바로 다음 번호를 시작할 수 있다.

## 이유

품질 파이프라인(깊이 게이트, 감산 규율, 크래프트 플레이북, 독립 평가)이 자리를 잡았으므로 생산량이 학습 속도를 결정한다. 하루 한 편 제약은 학습 반복을 인위적으로 늦춘다. 반복 지문·플레이 학습·크래프트 축적은 모두 편수에 비례해 쌓인다.

## 운영 규칙

- preflight는 날짜가 아니라 미완성·미공개 게임 존재 여부로 `resume-unfinished` / `resume-publication` / `create-next`를 권고하고 `nextSequence`를 제시한다.
- 저장소 디렉터리는 기존 `games/<YYYY>/<YYYY-MM-DD>-<slug>` 형식을 유지한다. 날짜는 실제 제작일이며 같은 날짜의 디렉터리가 여러 개 있을 수 있다. slug는 전 카탈로그에서 유일해야 한다.
- 카탈로그 `sequence`는 1부터 연속이어야 한다(기존 검증 유지). 교체 공개는 기존 번호를 계승한다.
- 품질 게이트는 편수와 무관하게 게임마다 전부 적용한다. 많이 만들기 위해 게이트를 낮추지 않는다.
