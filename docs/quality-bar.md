# Production Bar

> 세로형 모바일 디바이스에서 플레이할 수 있는 출시 품질의 체험판을 만든다.
> 실제 출시 게임의 핵심 루프를 어레인지한 버티컬 슬라이스이며, 콘텐츠는
> 제한하되 포함한 시스템과 아트·사운드는 임시 상태로 두지 않는다.

## 자유

- 장르, 규칙, 세션 길이, 종료·점수·실패 유무와 난이도는 자유다.
- DOM, Canvas, WebGL, WebGPU, 셰이더, 물리, 영상, 생성 이미지와 외부 자산을 자유롭게 사용한다.
- SVG, 아이콘과 절차적 기본 도형만으로 게임 아트 전체를 구성하지 않는다.
  실제 플레이의 정체성을 만드는 주 매체 하나 이상은 래스터 이미지, 페인팅,
  텍스처가 있는 3D, 영상, 셰이더 재질 또는 직접 그린 비트맵처럼 SVG가 아닌
  매체여야 한다. 파비콘, 검증 캡처와 잠금 뒤 공개 일러스트는 제외한다.
- 게임 규칙과 체험판 범위를 먼저 잠근 뒤 아트를 만든다. 고전 아트톤을 규칙
  선택의 입력으로 사용하지 않는다.
- 2D는 16비트 SNES 계열 도트 아트와 nearest-neighbor 확대를 사용한다.
- 3D는 PSX 계열 로우폴리, 저해상도 픽셀 텍스처와 낮은 내부 해상도 렌더를
  사용한다. 현대적 PBR·포토리얼 스타일은 사용하지 않는다.
- 선택된 장르의 실제 출시 게임 하나를 기준작으로 삼고 핵심 루프를 유지한다.
  변경은 2~3개 축으로 제한한다.
- 언어, HUD, 튜토리얼, 효과와 자원 규모를 의무화하지 않는다.
- 결정론, 자동 완주, 깊이, 목표 화면, 감산은 공개 조건이 아니다.
- 체험판의 콘텐츠 양은 제작자가 정한다. 포함한 시스템은 완성하고 범위 밖
  시스템은 빈 메뉴, 잠금과 “준비 중” 문구로 노출하지 않는다.
- `인트로 → 타이틀 → 게임 → 게임 결과` 네 상태와 결과에서 다시 시작하는
  경로를 반드시 제공한다.

## 제작자 검증

제작자는 자신의 GDD에 적은 게임 규칙과 로직에 필요한 테스트를 직접 정하고
작성해 통과시킨다. 공통 공정은 테스트 종류, 개수, 결정론, 자동 완주나 특정
입력 시나리오를 규정하지 않는다.

첫 구현은 릴리스 후보가 아니다. 제작 문맥을 받지 않은 새 플레이어가 실제
빌드만 플레이한 관찰을 제작자에게 돌려주고, 제작자는 그 관찰 가운데 작품에
유효한 것을 반영해 다시 만든다. 플레이어는 합격을 판정하지 않는다.

## 체르파 출고 판정

체르파는 최종 설계 문서의 구체적 약속이 실제 프로덕션 빌드에 구현됐는지,
제작자 테스트가 통과했는지, 그 빌드를 배포할 수 있는지만 확인한다. 설계의
재미·난이도·독창성·완성도와 테스트 방식은 심사하지 않는다.

## 배포 확인

- 세로 모바일 포털에서 빌드와 필수 자산이 로드되는지 확인한다.
- 콘솔·페이지·필수 요청 오류가 없는지 확인한다.
- 릴리스 파일의 경로, 해시와 불변 SHA를 기록한다.

게임의 플레이 결과는 공통 배포 스모크가 다시 판정하지 않는다. sequence 22까지의
게임은 당시 채택된 품질 기준과 공개 기록을 그대로 보존한다.
