# Daily production workflow

## 개념 선택

최근 게임과 겹치지 않는 물리적 동사를 고른다. 장르 조합이나 기능 목록을 아이디어로 취급하지 않는다.

내부 후보마다 다음 질문만 확인한다.

- 한 손의 한 입력으로 설명되는가
- 60초 안에 숙련 차이가 드러나는가
- 화면을 대표하는 재료감과 마지막 장면이 있는가
- 오늘 안에 코드, 아트, 사운드, 검증을 끝낼 수 있는가
- 최근 게임의 조작, 소재, 색과 구분되는가

가장 강한 후보를 고르고 아래 네 줄을 먼저 고정한다.

```text
조작:
재료감:
대표 색:
마지막 장면:
```

규칙을 한 문장으로 설명할 수 없으면 더 줄인다.

## 문서

구현 전에 게임 저장소의 문서를 채운다.

- `DAY.md`: 오늘 발견한 감각, 범위, 제외할 요소, 검증 계획
- `GDD.md`: 한 판의 순서, 결정론 규칙, 판정 수치, 점수, 화면, 소리
- `WHY.md`: 라이카가 이 게임을 만든 이유와 남긴 선택을 한국어·영어로 작성
- `ART.md`: 모든 이미지·사운드의 원본, 도구, 프롬프트, 후가공, 사용 위치
- `game.manifest.json`: 이름, 언어, 크레딧, 세션 길이, 조작, 일러스트 소스

공개 서사와 기술 명세를 섞지 않는다. `WHY.md`는 라이카의 말, 판정값과 계약은 `GDD.md`와 테스트가 소유한다.

새 저장소에서는 제품 식별자를 바꾼 뒤 lockfile의 루트 package 이름까지 확인한다. `gametemplate`, `GAME TEMPLATE`, `SampleGame`, `TODO_`, `placeholder`, 이전 게임의 slug가 남아 있으면 제작을 끝내지 않는다. 플랫폼용 미등록 광고·결제 코드는 게임 범위에서 제거하거나 비활성화하되, 외부 콘솔 값으로 가장하지 않는다.

## 규칙과 입력

- 입력 하나가 곧 핵심 판정이 되게 한다.
- 난수가 필요하면 시드를 주입하고 같은 입력이 같은 결과를 내게 한다.
- 시뮬레이션 시간을 렌더 프레임과 분리하고 복귀 프레임의 `dt`를 제한한다.
- 성공, 실패, 종료, 점수를 순수 함수로 분리해 먼저 테스트한다.
- 튜토리얼 화면보다 첫 장면과 첫 입력으로 규칙을 알게 한다.
- 재화, 상점, 업그레이드, 일일 보상, 광고, 결제는 기본 범위에서 제외한다.

## 화면과 접근성

- 논리 화면은 390×844를 기준으로 잡는다.
- 360×800, 390×844, 430×932에서 비율, 잘림, 가로·세로 넘침을 검사한다.
- 조작 영역은 한 손 엄지 범위와 44px 이상의 터치 목표를 보장한다.
- 텍스트는 상태와 조작을 설명할 때만 쓴다.
- 소리 없이도 성공과 실패를 구분할 수 있게 한다.
- 키보드와 포인터 입력을 함께 지원하고 포커스 표시를 숨기지 않는다.

## 한국어와 영어

- 화면 문자열을 코드에 흩어 쓰지 말고 번역 테이블에서 관리한다.
- 모든 키에 `ko`, `en` 값을 함께 둔다.
- 결과, 오류, 접근성 이름, 메타데이터까지 번역한다.
- 독립 실행에서는 게임 언어 선택기를 제공한다.
- 아케이드에서는 호스트의 `locale`을 따르고 내부 선택기를 숨긴다.
- 플레이 중 `setLocale` 호출로 상태를 보존한 채 언어를 바꾼다.

## 오늘의 라이카 그림

`brand/LAIKA.md`와 `brand/prompts/laika-style.md`를 읽고 다음 순서를 지킨다.

1. 게임의 마지막 장면을 한 문장으로 정한다.
2. `brand/art/laika-base.png`를 실제 이미지 참조로 전달한다.
3. 얼굴 무늬, 귀, 흰 가슴과 앞발, 크림색 X자 하네스, 주황 연결구를 고정한다.
4. 오늘의 도구 하나와 행동 하나만 바꾼다.
5. 문자, 로고, 서명, 가짜 역사 표식, 여분의 발, 사람 손을 거부한다.
6. 생성 원본을 `art/source/laika-<slug>.png`에 보관한다.
7. 카드용 640px, 상세용 1280px JPEG를 만든다. 원본 PNG는 릴리스하지 않는다.
8. 프롬프트와 해시, 얼굴·골격·문자·모바일 크롭 검수를 `art/`와 `ART.md`에 기록한다.

## 게임 아트와 사운드

- 게임 화면의 재료는 벡터, 셰이더, 절차 텍스처처럼 조절 가능한 원재료로 만든다.
- 생성 이미지를 완성 UI 전체로 사용하지 않는다.
- 대표 색 하나를 중심으로 두고 효과 색을 늘리지 않는다.
- 효과음은 입력의 결과를 설명하게 한다. 장식용 반복 효과를 넣지 않는다.
- AudioContext와 배경음은 첫 사용자 입력 뒤 시작한다.
- 숨김, 호스트 일시정지, 음소거, 재시작에서 모든 소리를 함께 제어한다.

## 아케이드 적응

현재 아케이드나 이전 게임의 도구가 특정 slug, 종료 결과, 자산 경로에 묶여 있을 수 있다. 등록 전에 runner, player, release builder, smoke driver를 검색한다.

- 게임 이벤트의 공통 envelope와 게임별 결과 payload를 구분한다.
- 포털은 점수를 문자열 하나로 표시할 수 있어야 하며 특정 게임의 단위나 성공 문구를 전역 기본값으로 두지 않는다.
- runner는 카탈로그가 넘긴 slug의 불변 prefix만 허용하고, 같은 slug의 `gameId`만 수락한다.
- 자동 플레이는 slug와 게임별 driver를 명시적으로 받는다. 이전 게임의 상태 필드나 목표 횟수를 새 게임에 강요하지 않는다.
- Vite가 `copyPublicDir: false`이면 릴리스에 필요한 공개 자산을 빌더가 모두 복사했는지 해시 목록과 실제 요청으로 확인한다.
- 문서 계약과 실제 이벤트 이름이 다르면 조용히 우회하지 말고 하나로 맞춘 뒤 양쪽 검증을 갱신한다.

공통화는 두 번째 게임에서 실제로 필요한 최소 surface만 한다. 오늘 게임의 규칙이나 결과 구조를 공통 runner에 새기지 않는다.

## 감산

첫 완성본 뒤 두 번 감산한다.

1. 중복 문구, 장식 배지, 기능 없는 효과, 필요 없는 메뉴를 제거한다.
2. 남은 요소가 핵심 입력, 재료감, 마지막 장면 중 하나에 기여하는지 다시 확인한다.

빈 공간을 새 요소로 채우지 않는다. 확보한 시간은 입력 촉감, 사운드 타이밍, 프레임 안정성에 쓴다.
