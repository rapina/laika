# Laika maker-narrative workflow

이 문서는 제작 잠금 뒤에만 읽는다.

## 작품 노트

완성된 게임을 직접 플레이하고 다음만 설명한다.

- 어떤 재미와 감각을 주고 싶었는지 — 콘셉트 잠금의 "노리는 재미와 감각"을 제작자의 말로. 노트의 첫 문장이 이것이어야 한다.
- 그 감각을 처음 느낀 순간과, 플레이어가 어디서 느낄 수 있는지
- 끝까지 남은 조작과 선택
- 감산 뒤 더 또렷해진 대표 장면

작동 방식이 아니라 느낌을 말한다. 판정 수치, 각도·ms·확률, 시뮬레이션 정책, 내부 상태 같은 메커니즘 설명은 작품 노트에 쓰지 않는다. 그것은 `GDD.md`와 검증 기록의 몫이다. "닿기 직전에 튕기면 대칭 분리된다"는 메커니즘이고, "실이 깊게 휘었다가 놓이는 순간의 손맛"은 감각이다.

라이카가 게임을 직접 만든 제작자로 설명한다. 주제와 선택의 이유는 잠긴 `DAY.md`, `GDD.md`, `ART.md`에서 가져오고 기록에 없는 동기나 결정을 만들지 않는다.

한국어와 영어가 같은 내용을 전달하게 한다. 한국어 `멍!`, 영어 `Woof!`는 각각 한 호흡만 사용한다. 긴 줄표(—, –)는 쓰지 않는다. 문장은 쉼표, 마침표, 가운뎃점으로 나눈다.

## 제작자 일러스트

1. 잠긴 마지막 장면과 대표 행동을 그대로 읽는다.
2. `brand/art/laika-base.png`를 실제 이미지 참조로 전달한다.
3. 얼굴 무늬, 귀, 흰 가슴과 앞발, 크림색 X자 하네스, 주황 연결구를 유지한다.
4. 잠긴 게임의 도구 하나와 행동 하나만 가져온다.
5. 문자, 로고, 서명, 가짜 역사 표식, 여분의 발, 사람 손을 거부한다.
6. 생성 원본을 `art/source/laika-<slug>.png`에 보관한다.
7. 카드용 640px, 상세용 1280px JPEG를 만든다. 원본 PNG는 릴리스하지 않는다.
8. 프롬프트, 해시, 얼굴·골격·문자·모바일 크롭 검수를 기록한다.

캡슐, 원형 창, 지구와 라이카 팔레트는 이 일러스트에만 쓴다. 게임 UI, 게임 아트, 게임 사운드에 추가하지 않는다.

## 공개 메타데이터

- `.studio.json`에 서사 준비 상태, 스튜디오, 제작자와 베이스 일러스트 정보를 유지한다.
- `game.manifest.json`의 잠긴 제목, 소개, 조작, 세션과 게임 미디어는 유지한다.
- manifest에는 `credits`, `whyCreated`, `media.makerIllustration`만 추가한다.
- manifest 크레딧은 `Sputnik Workshop` / `Laika` / `autonomous game-making agent`로 기록한다.
- 아케이드 카탈로그 `credits.model`과 관제 카탈로그 `model`에 게임을 실제로 만든 모델 ID를 기록한다(예: `claude-fable-5`, `gpt-5.6-sol`). 홈 목록과 작품 노트에 그대로 표시되며, 카탈로그 검증이 누락을 차단한다.
- 공개 크레딧은 `A game by Laika at Sputnik Workshop`을 기준으로 한다.
- 카탈로그 제작 노트는 기능보다 주제와 핵심 선택을 앞에 둔다.

## 제작 과정 공개 (designProcess)

작품 노트 페이지의 "제작 과정" 절에 들어갈 카탈로그 `designProcess`를 준비한다. 과정을 숨기지 않는 것이 원칙이다: 설계 문서, 목표 화면, 실제 화면, 검토 결과를 사람이 따라 읽을 수 있게 공개한다.

- `summary`: GDD의 질문과 코어 루프를 두세 문장으로 옮긴 설계 요약(ko·en). 판정 수치 표는 옮기지 않는다.
- `scenes`: 장면별(첫 판, 핵심 동사 직후, 게임 오버) 목표 화면과 실제 캡처 쌍. 이미지는 `arcade/public/art/design/<slug>/`에 target-*.jpg, actual-*.jpg로 복사한다(각 1280px 이하 JPEG). 장면 라벨과 한 줄 설명을 ko·en으로 쓴다.
- `review`: `design-review.json`의 `verdict`, `reviewedAt`과 `summary`, 주요 promises를 체르파의 문장(`brand/CHERPA.md`의 목소리, 기록체)으로 옮긴 것(ko·en). `review.reviewer`는 `Cherpa`다. 어조 변환만 허용하고 판정·사실은 바꾸지 않는다. gap으로 남은 항목도 숨기지 않고 적는다.
- 긴 줄표 금지 규칙은 designProcess의 모든 공개 문장에도 적용된다.
- 공정 기록(`arcade/public/catalog/process.json`)에 항목을 더할 때는 **배열 맨 앞에 넣는다.** 기록은 새것이 위로 보이고, 뒤에 덧붙이면 최신 항목이 첫날 아래로 내려간다. 카탈로그 검증이 날짜가 올라가는 차례를 거부한다.
- 공개 문장은 이 시스템을 모르는 사람이 읽습니다. 내부 용어를 그대로 쓰지 않는다: 공정, 자율 제작 에이전트, 대조, 간극, 보류, 전송·수신(세계관 제목 밖에서), 판정 구조, 밴드, 시뮬레이션. 쉬운 말과 동사로 푼다(내보내기 전 점검, 크게 어긋남, 공개를 멈춤, 실제로 나온 화면). 가운뎃점으로 네 개 이상 나열하지 않고, 게임 내부 수치 이름은 플레이어가 화면에서 보는 말로 바꾼다.

카탈로그 검증(`arcade/scripts/validate.mjs`)이 강제하는 형태와 길이는 다음과 같다. 이 값을 넘기면 등록이 거부된다.

```jsonc
"designProcess": {
  "summary": { "ko": ["문단", "…"], "en": ["…"] },   // 문단당 480자 이하, 1개 이상
  "scenes": [                                          // 3개 이상
    {
      "id": "first-play",                              // 소문자·숫자·하이픈, 중복 불가
      "label":  { "ko": "…", "en": "…" },              // 64자 이하
      "note":   { "ko": "…", "en": "…" },              // 선택, 320자 이하
      "target": { "url": "/art/design/<slug>/target-<id>.jpg", "width": 0, "height": 0 },
      "actual": { "url": "/art/design/<slug>/actual-<id>.jpg", "width": 0, "height": 0 }
    }
  ],
  "review": {
    "reviewer": "Cherpa",                              // 고정
    "reviewedAt": "YYYY-MM-DD",
    "verdict": "pass",                                 // blocked는 공개 불가이므로 카탈로그에 실리지 않는다
    "summary": { "ko": "…", "en": "…" },               // 480자 이하
    "checks": [                                        // 1개 이상
      { "status": "pass",                              // sequence 22부터 pass
        "claim":    { "ko": "…", "en": "…" },          // 320자 이하
        "observed": { "ko": "…", "en": "…" } }         // 320자 이하
    ]
  }
}
```

검토가 한 번이라도 공개를 막았다가 보완 뒤 통과했으면 `review.held`를 함께 등록한다. blocked 상태는 카탈로그에 실릴 수 없으므로, 막았다는 사실은 여기에만 남고 홈의 관제 기록에 집계된다.

```jsonc
"held": { "at": "YYYY-MM-DD", "reason": { "ko": "…", "en": "…" } }   // 480자 이하
```

`earthReview`의 `impression`·`worked`·`friction`·`carry`는 각 320자 이하이며, 무르 일러스트는 `/art/murr-<slug>-640.jpg`와 `-1280.jpg` 두 장이 실제로 있어야 한다. 이미지 파일이 없으면 검증이 거부한다.

`.creator-lock.json`은 읽기 전용이다. 라이카 제작 서사 뒤 제작 잠금 검증을 실행한다. 잠긴 파일이 바뀌면 서사 작업을 되돌리고 공개를 중단한다.
