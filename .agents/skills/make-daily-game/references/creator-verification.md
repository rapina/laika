# Creator verification

검증은 게임 규칙을 특정 구조로 몰아가지 않고 치명 결함만 찾는다.

## 필수

프로젝트에 실제로 존재하는 명령만 실행한다.

1. 프로덕션 빌드
2. 현재 sourceHash를 기록하는 부팅 스모크
3. 포털 CSP·필수 자산 로드 확인
4. 360×800, 390×844, 430×932 세로 화면 확인
5. 화면에 보이는 주 입력을 실제 포인터로 한 번 이상 수행
6. 콘솔·페이지 오류 확인

게임이 종료되지 않는다면 스모크는 짧은 상호작용 뒤 성공할 수 있다. 결과 전달,
자동 완주와 재시작을 만들게 하지 않는다. 게임이 해당 기능을 제공할 때만 실제로
작동하는지 확인한다.

## 선택

다음은 게임이 원하거나 제작에 도움이 될 때만 수행한다.

- 단위 테스트와 결정론 테스트
- 플레이 가능성 시뮬레이션
- 사람 모델 여러 판 비교
- 목표 화면과 실제 화면 대조
- 결과·점수·게임 오버·재시작
- 한국어·영어 기능 대조
- DPR, 프레임 시간과 성능 목표

선택 검증의 실패는 치명 결함이 아니라면 공개를 막지 않는다. 실행한 명령, 실제
결과와 확인하지 못한 부분을 `DAY.md`에 그대로 기록한다.

## 증거

- `smoke-result.json`은 최소한 `sourceHash`, `mounted`, 오류 목록과
  `interactionVerified`를 기록한다.
- 종료형 게임이면 `finished`, `resultDelivered`, `restartVerified`를 추가할 수 있다.
- 캡처와 수치는 만든 경우에만 커밋한다.
- 소스나 필수 자산이 바뀌면 부팅 스모크를 다시 실행해 sourceHash를 갱신한다.
