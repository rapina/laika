# Narrative, release, and publication verification

## 출고 검사

- `design-review.json`은 schemaVersion 2의 fatal-only 검사다.
- 여섯 `fatalChecks`가 pass이고 `verdict: "pass"`다.
- `sourceHash`가 현재 `smoke-result.json`과 같다.
- 난해함, 미완주와 비차단 notes는 고치지 않고 공개 기록에 옮긴다.

## 제작 서사

잠금 뒤 `WHY.md`, 공개 카피, 크레딧과 라이카 제작자 일러스트를 작성한다.
잠긴 게임의 규칙·세계·아트·사운드를 브랜드에 맞춰 바꾸지 않는다. 아케이드
작품 노트는 한국어와 영어로 제공하되 게임 자체의 언어 선택은 제작자에게 맡긴다.

## 릴리스

- 프로덕션 빌드와 아케이드 엔트리를 만든다.
- 모든 파일의 경로, SHA-256, 파일 수와 바이트를 `release.json`에 기록한다.
- 생성 원본과 개발용 source map을 릴리스에 싣지 않는다.
- 자원 크기는 기록하되 창작 차단 예산으로 사용하지 않는다.

## 로컬·preview·production

아케이드 카탈로그, 플레이 페이지와 불변 자산 경로를 확인한다. 프로덕션 스모크는
fatal-only 모드를 사용한다.

- 포털과 게임이 뜬다.
- 세로 화면에서 핵심 영역이 보인다.
- 실제 포인터 입력 뒤 화면이 반응한다.
- 콘솔·페이지·필수 요청 오류가 없다.
- 게임이 종료형이면 결과 경로까지 확인할 수 있지만 완주는 모든 게임의 의무가 아니다.

목표 화면과 `designProcess.scenes`는 선택 사항이다. 체르파 요약과 치명 검사
결과는 공개할 수 있다.

## 지구 플레이

첫 공개 뒤 운영 URL에서 실제로 플레이한다. 완주하지 못해도 경험한 범위만
한·영 기록에 남기고 공개를 유지한다. 깊이·재도전 평가를 의무화하지 않는다.

Toss 제출, 비용·계정·도메인 변경과 결제·개인정보 수집은 별도 운영자 승인이다.
