# Brand-blind creator workflow

## 후보 확장

서로 다른 조작과 시스템 반응을 가진 후보를 네 개 이상 만든다. 장르 이름이나 배경만 바꾼 후보는 하나로 본다.

후보마다 다음을 확인한다.

- 한 손의 주 입력으로 시작할 수 있는가
- 진행 중 목표, 위험, 공간 또는 리듬이 변하는가
- 60초 안에 숙련 차이가 드러나는가
- 재료와 시각 매체가 조작 결과를 보여 주는가
- 마지막 장면이 정지 화면으로도 식별되는가
- 오늘 안에 코드, 게임 아트, 사운드와 검증을 끝낼 수 있는가
- 최근 반복 지문과 구분되는가

가장 강한 후보 하나를 고른다. 사용자가 고르게 하지 않는다. 한 조작은 한 상태만 반복한다는 뜻이 아니다. 같은 입력에도 상황에 따라 다른 판단과 결과가 생겨야 한다.

## 콘셉트 잠금

다음 항목을 채운 뒤 세계와 기능을 늘리지 않는다.

```text
제목:
질문:
핵심 입력:
시스템 반응과 긴장 변화:
재료:
시각 매체:
대표 색:
세계:
마지막 장면:
한 판 길이:
제외할 요소:
```

래스터 이미지 사용량을 목표로 삼지 않는다. 벡터, 절차 그래픽, 3D, 촬영·생성 이미지 중 대표 장면을 가장 잘 만드는 매체를 고른다. 절차 그래픽만 쓸 때는 단순한 도형 배치로 끝나지 않는지 별도로 검토한다.

## 문서

- `DAY.md`: 콘셉트 잠금, 반복 회피, 범위, 검증 결과
- `GDD.md`: 한 판의 순서, 규칙, 판정 수치, 점수, 화면, 게임 아트와 소리
- `ART.md`: 게임 이미지와 사운드의 원본, 도구, 프롬프트, 후가공, 해시와 사용 위치
- `game.manifest.json`: 한·영 제목과 소개, 조작, 세션, 게임 미디어와 릴리스 식별자

manifest에 `credits`, `whyCreated`, `media.makerIllustration`을 넣지 않는다. `WHY.md`, 공개 카피, 크레딧과 라이카 일러스트는 만들지 않는다.

## 규칙과 입력

- 난수에는 시드를 주입하고 같은 입력이 같은 결과를 내게 한다.
- 시뮬레이션 시간을 렌더 프레임과 분리하고 복귀 프레임의 `dt`를 제한한다.
- 성공, 실패, 종료, 점수를 순수 함수로 분리해 먼저 테스트한다.
- 설명 화면보다 첫 장면과 첫 입력으로 규칙을 알게 한다.
- 재화, 상점, 업그레이드, 일일 보상, 광고, 결제는 기본 범위에서 제외한다.

## 화면과 접근성

- 논리 화면은 390×844를 기준으로 한다.
- 360×800, 390×844, 430×932에서 비율, 잘림과 넘침을 검사한다.
- 조작 영역은 한 손 엄지 범위와 44px 이상의 터치 목표를 보장한다.
- 텍스트는 상태와 조작을 설명할 때만 쓴다.
- 소리 없이도 성공과 실패를 구분할 수 있게 한다.
- 키보드와 포인터 입력을 함께 지원하고 포커스 표시를 숨기지 않는다.

## 한국어와 영어

- 화면 문자열은 번역 테이블에서 관리한다.
- 모든 키에 `ko`, `en` 값을 함께 둔다.
- 결과, 오류, 접근성 이름, 메타데이터까지 번역한다.
- 독립 실행에서는 언어 선택기를 제공한다.
- 아케이드에서는 호스트의 `locale`을 따르고 내부 선택기를 숨긴다.
- 플레이 중 언어를 바꿔도 상태를 보존한다.

## 게임 아트와 사운드

- 선택한 시각 매체를 실제 게임 화면에 충분히 사용한다.
- 생성 이미지를 완성 UI 전체로 사용하지 않는다.
- 대표 색을 중심으로 두되 재료의 깊이를 없애지 않는다.
- 효과음은 입력과 시스템 반응을 설명하게 한다.
- AudioContext와 배경음은 첫 사용자 입력 뒤 시작한다.
- 숨김, 호스트 일시정지, 음소거, 재시작에서 모든 소리를 함께 제어한다.

## 감산

첫 완성본 뒤 두 번 감산한다.

1. 중복 문구, 기능 없는 효과, 불필요한 메뉴와 진행 체계를 제거한다.
2. 남은 요소가 질문, 조작, 시스템 반응, 재료, 마지막 장면 중 하나에 기여하는지 확인한다.

빈 공간을 새 요소로 채우지 않는다. 확보한 시간은 입력 촉감, 시각 매체의 완성도, 사운드 타이밍과 프레임 안정성에 쓴다.
